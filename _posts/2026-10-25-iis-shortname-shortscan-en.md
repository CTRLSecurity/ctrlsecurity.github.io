Some Windows volumes retain an 8.3 short name alongside a file's full name. A file named `financial-report.aspx`, for example, may have a short alias generated by the file system. The exact alias depends on its directory, collisions, and volume settings; it cannot be safely guessed from the long name alone.

Under certain combinations of IIS, file system, and configuration, requests containing `~` yield different responses for existing and nonexistent short-name prefixes. That difference can let a tester **infer parts of names** the application did not intend to list. The signal comes from observed server behavior, not merely from a tilde in a filename.

## What a discovery means

A matching 8.3 prefix may reveal directory structure or likely filenames. It can guide further checks, but **does not prove file reading, source disclosure, or command execution**. A content-exposure claim needs a separate request that returns the expected content with suitable controls. WAF blocks, caching, and custom error pages can also produce misleading differences.

## Where shortscan helps

[shortscan](https://github.com/thezakman/shortscan), developed by bitquark and TheZakMan, automates detection and enumeration of IIS short filenames. After finding a short name, it attempts to recover the full filename using autocomplete methods. The project also documents a checksum matching approach for some short-name collision cases.

In an authorized environment, check for the exposure signal before running full enumeration:

```sh
shortscan --isvuln https://iis.example.test/
```

If the signal is stable and enumeration is in scope, run a targeted scan. `--fullurl` makes it easier to record the path of a confirmed file; `--autocomplete auto` lets the tool choose a recovery strategy.

```sh
shortscan --fullurl --autocomplete auto https://iis.example.test/app/
```

These are examples. Adjust rate, headers, and path to the environment and scope. The first check also sends requests; it is not a purely local analysis.

## Validate the result

1. Compare a candidate prefix with nonexistent prefixes using the same method, headers, and session.
2. Repeat the comparison in the same directory. A route or cache-layer change invalidates the control.
3. Keep the requests and responses supporting each inference, including negative results.
4. Separate three levels in the report: differential behavior, enumerated short name, and confirmed long name.

For remediation, inspect the IIS setup and affected volumes first. Windows provides `fsutil 8dot3name` to query and control 8.3 name creation. Disabling future creation does not automatically remove existing aliases. Stripping them without analysis can break applications that depend on them; Microsoft recommends assessing the impact and backing up before doing so.
